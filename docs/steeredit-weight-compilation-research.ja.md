# SteerEditを参考にしたCLEの重みコンパイル調査

調査日: 2026-09-27。対象: Heretic `3521f86`、[SteerEdit / arXiv:2604.12359v1](https://arxiv.org/html/2604.12359)、[CLE / arXiv:2605.21706v2](https://arxiv.org/html/2605.21706v2)。SteerEditは [ACL 2026の論文ページ](https://aclanthology.org/2026.acl-long.1206/) も確認した。

**結論: 参考になる。CLEの活性化補正を較正データ上で近似する重み更新を求めれば、構造を変えず、hook不要の通常モデルとして書き出す設計が可能。全入力での厳密な同値変換とは区別する。実モデルでの性能は未検証。**

前の説明で挙げた専用runtimeと蒸留に加え、閉形式の回帰による近似コンパイルを検討すべきだった。「入力依存だから固定重みにできない」という言い方は広すぎる。固定重みでも `ΔW k(x)` は入力依存の補正になる。問題は、必要な補正を利用可能な特徴kから表現できるかどうかである。

## 論文で確認したこと

SteerEditはMLPのdown-projectionを編集する。中間特徴Kから所望の活性化変化への写像を正則化最小二乗で求め、保護用特徴K₀のnull spaceに更新を制限する。最適化問題の閉形式解があり、得られた差分を元の重みへ加える。論文の実験設定はtrigger付き入力への一定方向の介入であり、CLE-P/CLE-Aのコンパイルを実証したものではない。[Sections 5.2–5.4 / Appendix B](https://arxiv.org/html/2604.12359)

閉形式解は指定した回帰問題の最適解である。正則化、特徴のrank、目標との整合性によって目標値に残差が生じる。また、実用上のnull spaceは小さな特異値を含む近似で、保護データ以外も含めた無変化を保証するものではない。

論文本文・ACLページとGitHubを対象にした公開検索では、著者による公式コードの所在は確認できなかった。非公開・未公開と断定はしない。本調査のSteerEdit部分は論文に基づく。

## CLEへの適用案: 以下は今回の導出であり論文の実証結果ではない

通常のLlama型blockでは、MLP後の残差を簡略化して次のように書ける。

```text
h = r + W k
```

rはMLPに入る前のresidual stream、kは `down_proj` の入力、Wはその重み。実際のgated MLPではkは活性化関数とgate/upの積を経た特徴である。

Wを `W+ΔW` にすると、同じblock入力・同じkに対する局所的な変化は `ΔW k` になる。したがって、CLEが求める補正 `d_i` と特徴 `k_i` を集めて `ΔW k_i ≈ d_i` を満たす更新を求めればよい。この条件は、すでに編集された上流層がkを変える点までは解消しない。

### 単方向は、入力依存でもrank 1を保てる

CLE-Pの補正は、固定された層のプローブwについて次の形である。

```text
d(h) = w c(h)
c(h) = -β (wᵀh + b + m) / ||w||²
```

係数cを `aᵀk` で近似すれば、`ΔW = w aᵀ` となりrankは高々1。入力ごと・トークンごとにcが変わること自体は、rankを増やす理由ではない。

ただし `wᵀr` と定数項b+mをkから予測できるとは限らない。Wk由来の項だけを代数的に吸収しても、CLE-P全体は再現されない。biasがない既存構造では非ゼロの定数補正を全入力で保証することもできず、較正分布上の近似として扱う。

CLE-Aも各層の補正は1本のw上にあるので、局所目標のrankは高々1。ただし係数はprompt全体で決まり、その後の全位置で共有される。各時点のkから同じ係数を再現できるかは、CLE-Pとは別に検証する。

### 多方向も低rankの形で扱える

固定したK方向が張る部分空間の正規直交基底を `U ∈ R^(d×K)`、各サンプルの目標係数をCと置くと、補正目標は `D=UC` と書ける。非直交の元の方向は、元の境界・marginの意味を保ったまま補正Dを計算してから、基底U上の係数へ変換する。

保護用のMLP特徴に対するnull-space基底を `Q ∈ R^(d_m×q)` とし、`X=QᵀK_train` を使うと、次の回帰を考えられる。

```text
A* = argmin_A ||A X - C||_F² + λ ||A||_F²
A* = C Xᵀ (X Xᵀ + λ I)^(-1)       (λ > 0)
ΔW = U A* Qᵀ
```

UとQを正規直交とした場合、これは制約された重み差分についてのFrobeniusノルム回帰と対応する。逆行列を明示計算せずsolveを用いる。LoRAでは `B_lora=U`、`A_lora=A*Qᵀ` とでき、rankは高々K。単方向ならUを正規化したwとし、Cにもそのスケールを反映する。

このrank上限は、固定方向に沿う局所的な補正を近似する場合のもの。編集済みモデルとteacherの累積状態差まで補償する目標は、同じK次元部分空間に収まらない可能性がある。

Hereticのgood平均に対する方向直交化と、ここでのQは別物である。前者は出力側のresidual空間、後者は入力側のMLP中間特徴空間に作用する。

## 条件と限界

| 論点 | 統合時の判断 |
| --- | --- |
| 通常HFモデルとして保存 | ΔWを既存Wに加えれば可能。独自forwardやhookを配布する必要はない |
| runtime CLEと厳密に同じか | 保証しない。局所回帰誤差と自由生成の差を測定する |
| 多方向との組み合わせ | 固定K方向の局所目標ならrank K以下の回帰に整理できる |
| benign保護 | 較正データ上の近似的な制約。未見データへの保証とはしない |
| GGUF等の既存エンジン | 元architectureを維持する利点がある。元モデルの対応状況と量子化後の効果は別途検証 |

**保護と再現の競合:** CLEは通常、harmless入力にも変換を適用する。その変化が非ゼロなら「harmlessでは重み編集の効果をゼロにする」と「runtime CLEをその入力でも再現する」は同時には満たせない。今回の用途ではtriggerの導入を前提にせず、CLE再現用データと能力保持用データをどう扱うかを明示的に定義する。

同じ特徴kについて、保護条件が `ΔWk=0`、較正目標が `ΔWk=d≠0` なら矛盾する。目標側の特徴が保護部分空間にほぼ含まれる場合も、近似精度と保護の強さが競合する。hard constraintだけでなく `||ΔW K_protect||²` のsoft penaltyを比較する価値がある。

**CLE-Aの因果性:** 確認済みの公開CLE-Aは、prompt全体から得た補正を、生成時prefillの過去位置にも加える。同じprefixで末尾が異なる2つのpromptは、同じ過去位置でも補正量が異なり得る。通常の一回のcausal forwardでは、その位置の状態は未来のprompt suffixを参照できない。したがって、追加passなしで全位置の内部状態を厳密に一致させる要求には構造的な制約がある。最終的な生成挙動を近似することまで否定するものではない。[公開CLE-A](https://github.com/pralab/latent-evasion/blob/5f60ff9eaa913be6b82585407de9c54d7809b220/cle-a.py)

**MLP出力後の非線形処理:** ローカルTransformersのLlamaはMLP出力をそのままresidualに足す。一方、Gemma3は `post_feedforward_layernorm` を経てから足す。この場合、down-projでのΔWkはblock出力の同じ加算量にならない。構造に応じて目標位置を変更・再定義するか、非線形な較正が必要。単一の線形コンパイラを全architectureへ無検証で適用しない。

**層間・生成中の分布変化:** 上流の編集後には下流の特徴が変わり、生成token自体も変わる。各層を元モデルの特徴だけで独立にfitして終了とはしない。層順の再採取・再較正や、teacherとstudentに同じtoken列を与える診断、studentの自由生成による確認が必要。prompt末尾のみの較正結果から全decode位置の精度を推定しない。

コンパイル版は、既存abliterationのA/Bをそのまま使うのではなく、較正によって新しく求めたA/Bを保持する。併用する場合は重み差分とrankの管理を明示する。

量子化モデルでの較正と、元の非量子化重みへのマージは同じbase演算とは限らない。まず非量子化denseモデルで評価し、再量子化後にも測定する。出力checkpointは通常形式にできるが、再現用メタデータにはteacherのCLE設定、採取位置、データ・モデルrevision、rank、保護方式、正則化を残す。

大きなMLPで `d_m×d_m` の射影行列と擬似逆行列を毎層作るのは避けたい。例としてd_m=11008ならFP32の正方行列1枚だけで約462 MiB。基底上のsolveや、サンプル数に応じたdual形式、特徴の逐次採取を検討する。null-space基底自体が巨大になる場合もあり、低rank LoRAだから較正コストも小さいとは限らない。

## 数値検証

既存 `.venv` のPyTorchを使用し、CPU/FP64の合成特徴で数学的な接続を確認した。LLM・学習データ・triggerは使用していない。

| 確認内容 | 結果 |
| --- | --- |
| 入力8次元・出力6次元・2方向の合成teacher | rank 2のLoRA形で表現可能 |
| 基底上のsolveと射影行列＋擬似逆行列の差 | 最大約4.6e-15 |
| 指定した厳密な保護部分空間への変化 | 0 |
| マージ後の未見合成特徴での相対誤差 | 約8.1e-11 |
| 保護特徴に非ゼロ目標を同時指定 | 厳密な保護では目標を実現できない |
| MLP後にRMS正規化を加えた場合 | 同じ加算量という仮定が破れることを確認 |

teacherは特徴から線形に表せるよう構成した。これは低rank回帰とマージの整合性の確認であり、CLEが実モデルのMLP特徴から同程度に近似できることの証拠ではない。

## 推奨する次段階

最初の対象は、MLP出力後に追加normがないdenseモデルの単方向CLE-P。runtime CLEを比較基準として用意し、promptとdecodeの較正からrank 1の重み更新を求め、通常モデルとして保存・再ロードする。

比較対象は「元モデル、現行Heretic、runtime CLE-P、compiled CLE-P」。局所補正の誤差だけでなく、出力logit差、未見promptでの挙動、一般能力、速度、保存後の一致を評価する。次にK方向、CLE-Aへ広げる。

保存モードは `runtime_exact` と `compiled_approx` のように区別できる。前者も指定した実装仕様への忠実性を意味し、論文数値の再現を自動的に保証する名前にはしない。後者について「CLEと完全同値」とは表示しない。今回の変更は調査文書のみで、コンパイラ本体は未実装。
